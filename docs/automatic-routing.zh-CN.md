# 探测站向调度站自动推送

更新：2026-09-21。完整页面、数据流和功能边界见 [当前项目全部功能与运行逻辑](project-functional-logic.zh-CN.md)。

## 数据方向

唯一线路来源是本监控项目（探测站）已经接入的上游渠道及其令牌：

上游渠道 → 本站令牌与模型探测 → 可用模型白名单 → Sub2API 调度站点。

调度站点的分组和账号读取仅用于选择推送目标、核对 URL / Key、防止重复创建，以及确认写入结果。绝不从调度站点账号新建本站渠道或探针。

入口为“线路管理 → 自动调度”。页面每一行代表本站令牌的一类接口协议，显示来源、目标分组、推送状态和可用模型。同一令牌有不同协议时分别管理兼容的调度账号。

## 自动接入

上游开启“自动探测新令牌”后，后台只同步上游已有 Key、自动获取模型并探测。本站不创建上游令牌；没有 Key 的分组需先在上游创建，再等待同步。历史配置和旧客户端也不能触发补齐令牌。已有手动停用令牌不替换、不自动开启。高级维护中的扫描仍会展示全部分组和缺少令牌的情况。

## 推送条件

- 只采用本站已启用探测、凭据有效的上游令牌。
- 模型必须在最近两分钟内实际探测成功，才可进入调度白名单；模型目录声明不代表可用。
- URL、完整 Key 和平台匹配时复用已有调度账号，不重复创建。
- 探测站新建的调度账号并发数统一为 1000。
- 新线路根据上游分组名称、模型家族及等级匹配目标分组。只有一个明确目标才自动选择；多义或无匹配时在页面选择。
- 自动新建要求倍率成本可核算，按充值倍率折算并考虑上游高峰加价，折算成本倍率不高于调度站分组倍率即可，不设百分比门槛。相等允许，高于时暂停对应模型探测与托管调度。
- 倍率达标且验证正常的线路全部参与调度，同一分组、同一模型允许多条线路同时承接。取消主用与备用互斥，不再根据排名关闭正常线路。
- 图片、视频等尚无专用探针的模型不自动推送。
- 创建前保存意图，超时后只回读核对，不盲目重新创建；成功后读取账号确认 URL、Key、分组。

## 持续更新与恢复

正常模型每分钟探测。验证失败的模型从调度白名单移除；探测历史保留。推送流程为相关启用令牌开启自动模型恢复，这些令牌的模型在明确不支持或连续三次失败时隔离，通常每五分钟重新验证，成功后自动回到白名单。未开启自动恢复的普通令牌仍需区分手动复核。

已有线路若本轮无模型通过，但原白名单中仍有最近 120 秒内成功过、此次仅超时、连接异常、上游暂时异常、限流或响应未确认的模型，进入“短暂异常观察”，暂时保留这些模型。观察期限从上次成功开始计算，新失败或服务重启不会延长。只保留原有明确模型，不添加新模型或通配符，也不重新打开已经暂停的线路。认证、权限、额度等明确错误和自动隔离模型不适用。仍有其他模型本轮通过时，继续逐模型隔离。

观察期内成功则恢复正常标记；成功证据超过两分钟且没有新成功时暂停调度。观察模型不计为本轮验证通过。时间轴显示最近 60 个已结束分钟，页面当前状态另含本分钟最新结果，两者可能暂时不同。日志记录暂停原因、决策时模型结果及最近成功时间。

账户余额已确认不足、令牌不可用、本站停用探针或整条线路无近期成功模型时，关闭对应调度账号的调度开关。单个模型的认证、额度、限流等错误通常只移除该模型，其他成功模型继续使用。所有模型失败时不写空白名单，因为 Sub2API 的空映射代表允许所有模型。已有 OpenAI 透传会绕过模型映射，不能单独隔离失败模型，因此保留整线保护；新账号默认关闭透传。

本站来源移除或更换凭据时，核对并暂停其此前接管的目标；不会根据调度站配置反向补回来源。整线恢复需至少一个保留模型在暂停后连续两轮验证成功，余额不再阻断，再同步可用模型并开启调度，不要求全部失败模型一起恢复。余额不足导致的冷却可在有效正余额和探测恢复证据确认后解除；限流、过载等其他冷却仍需遵守。

本站当前添加入口使用上游账户授权查询真实余额，不提供单独粘贴模型 Key 的完整上游接入表单。不能用单个模型返回的额度错误，替代整个钱包余额的确认。

## 统一自动管理与迁移

已关联账号统一自动管理，删除逐线路接管开关和历史手动保护状态。远端原本停用、变为 inactive 或被外部切换开关时，由后台重新核对；停用账号通过两轮新的成功验证后自动恢复。模型白名单按探测结果维护。URL、Key 或目标分组不匹配时显示配置错误并自动重试，不能把其他凭据当作已验证来源。

站点总开关关闭时暂停自动写入，保留远端当前配置；需要停止某条线路时，关闭对应探针，后台会暂停其关联的调度账号。生产服务执行推送，本地开发不启动自动调度执行器，也不自动开启本地探测。

旧版本从调度站反向导入的内部探针全部停用归档，不再出现在探针监控或参与识别；保留原历史和加密记录供追溯。旧的自动调度状态保存为迁移记录，升级后由正向推送接管。调度站原有账号不会因为归档而被删除。

## 接口与存储

- `POST /api/secondary-sites/:id/automation`，`{"enabled":true|false}`：站点自动推送开关。
- 同一接口，`{"routeId":"...","enabled":true|false,"groupId":123}`：本站令牌线路的目标和接管设置；目标确定后持续自动更新。
- `GET /api/secondary-sites` 返回 `automation.routes`，只包含本站来源和脱敏推送状态。

配置、来源身份、创建意图、远端写入确认和历史继续保存在现有 SQLite 加密记录中。只有一个 API / 调度进程执行写入。

## 调度日志

日志中心集中保存调度决策、远端写入确认、模型名单修改前后、人工接管、推送失败及恢复记录。调度页面的“查看此站点的完整日志”会自动按站点筛选。本站 SQLite 独立保存操作记录，调度页最近 100 条只是摘要；模型探测明细沿用每模型最多 1,440 条的既有历史规则。完整范围和保存规则见功能逻辑文档第 13.7 节。


## 探针判定边界（2026-09-22 修正）

- 收到文本但输出被截断、流式中断或响应明确未完成时，显示“响应未确认”，不计为通过，也不作为模型不存在的证据。
- Chat 流已收到 `finish_reason`，不必继续等待代理关闭连接；正常结束标记优先于上游可能不准确的用量数字。
- 上游明确要求流式时，下一正常探测周期使用流式，并保留这个接口要求。接口或参数不兼容单独显示，不当作模型被上游拒绝。
- 模型的探测协议由 Chat 切到 Responses 后，已推送账号如果仍强制使用 Chat，会解除这个旧设置，并回读确认。
- “模型已隔离”可能来自模型被明确拒绝，也可能来自连续失败。详情显示实际原因；已开启自动恢复的令牌每五分钟复测。
- 短暂异常仍只保留最近成功起两分钟内的原有模型；不新增未经验证的模型，不据此打开已暂停账号。余额、令牌、倍率和恢复条件仍生效。

一次低 token 的健康探测只验证当次请求。它不能证明上游模型身份、长上下文能力、工具调用或真实业务并发下的成功率。输出上限仍保留，推理预算耗尽时显示未确认，不靠无上限重试换取通过。历史记录不改写，需要后续新样本验证修复效果。
