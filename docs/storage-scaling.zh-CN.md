# 百渠道规模的存储优化

## 数据现在保存在哪里

线上业务数据保存在 `/var/lib/signal-monitor/monitor.sqlite`，使用 Node.js 24 内置 SQLite，不需要额外安装数据库服务器。

- `records`：上游渠道、调度站点配置、线路绑定、授权信息、令牌、模型当前状态、充值操作状态和控制台设置。
- `probe_history`：以渠道、令牌、模型、记录序号为索引的探测历史。
- `metadata`：迁移完成标记、迁移校验摘要和加密校验信息。

配置与历史正文使用原来的 `storage.key` 进行 AES-256-GCM 加密。用于查询的标识、时间、状态索引不加密。数据库、密钥及目录仅允许服务账号访问。登录会话仍单独保存在 `console-sessions.json`；浏览器 IndexedDB 只是显示缓存，不是业务数据源。

## 解决的问题

以前每轮探测会把所有渠道与历史序列化、加密后重写整个 JSON。现在后台按实际变动的渠道更新配置，历史只追加新结果。事务提交失败时，不发送需要先持久化预约的模型请求，不丢弃旧授权，也不提交半批探测开关。

数据库使用 WAL 与 `synchronous=FULL`。同一轮并发结果短暂合并后提交，保留每个令牌的每个模型每分钟探测的现有规则。依然只运行一个 API/调度服务进程；不要直接启动多个进程共享同一份内存业务状态。

后台常驻内存只加载最近 65 分钟及末尾 8 条记录。持续失败次数、尚未恢复的模型拒绝和最近成功时间另存摘要，避免缩小历史窗口后把异常误显示为正常。

页面继续展示最近 60 个完整分钟。轮询返回近期记录；结果未变化时返回 HTTP 304。浏览器隐藏时暂停页面轮询，不影响服务器探测。模型时间轴只在对应行展示时计算，折叠的异常详情不创建大量隐藏节点。同一模型的线路每次展示 25 条，可继续展开；搜索和批量操作仍覆盖全部匹配令牌。

## 历史保留规则

每个“渠道 + 令牌 + 模型”保留最近 1,440 条探测结果，与原来的上限一致。按一分钟一次通常约为 24 小时；暂停期间不会凭空产生记录。页面显示窗口和数据库保留窗口是两件事。

首次迁移逐条保留旧文件中的全部记录，不主动删减；后续写入继续执行原有保留上限。持续异常摘要保留到真实探测成功，不因一分钟时间轴滑动而清除。

数据库通常复用过期记录释放的页面，文件不一定立即变小。不要频繁运行 VACUUM，以免阻塞写入。

## 自动迁移与发布

首次启动按数据类型从旧加密 JSON 迁移到 SQLite。迁移在事务中完成；读取解密后的数据库结果，与原始对象逐项比较一致后才写入完成标记。旧 JSON 保留原样；后续启动读取数据库，不再从旧快照覆盖新数据。

发布脚本会：

1. 验证干净发布包，不上传本地渠道或密钥。
2. 停止服务，把服务器数据目录和登录配置备份到 `/var/backups/signal-monitor/<时间>/data.tar.gz`。
3. 以服务账号执行迁移，核对完整业务数据摘要、历史数量、渠道、调度站点、关联和密钥。
4. 启动服务并验证访问。

如果需要降级到只认识 JSON 的旧版本，必须先停止服务，再用新版本的 `exportLegacySnapshots()` 把最新数据库导出成加密 JSON。不能直接切换旧代码，否则可能读取过期的刷新令牌。发布脚本在失败回退时执行该步骤；导出失败则停止回退，保留数据库，避免覆盖新凭据。

## 备份与恢复

最直接的完整备份方式是在停止服务后备份整个 `/var/lib/signal-monitor` 和 `/etc/signal-monitor/auth.json`，完成后再启动。运行中不要只复制 `monitor.sqlite`，因为最新事务可能仍在 `monitor.sqlite-wal` 中。

恢复时应停止服务，整体恢复同一份备份中的数据库和 `storage.key`，确保数据归属 `signal-monitor:signal-monitor`、目录权限 0700、数据文件权限 0600，再启动对应版本。密钥缺失时程序拒绝重新生成密钥覆盖已有数据。

迁移后旧 JSON 是当时的迁移备份，不是持续更新的备份。恢复旧快照会丢失之后的编辑与探测记录，上游刷新令牌也可能已失效，需要重新授权。

## 可重复的容量检查

在项目目录运行：

```sh
node --test server/sqlite-store.test.js
node --expose-gc scripts/benchmark-storage.mjs
```

压测只使用临时目录中的合成数据，不访问上游，不启动真实探测。默认规模为 120 个渠道、240 个令牌、1,200 个令牌与模型组合、1,728,000 条历史。

检查包括：迁移完整性、凭据加密、写入失败回滚、重启、历史保留上限、内存窗口、重复轮询 304，并验证追加一轮结果不会重新加密或改写旧历史。

本机首轮测量：探测预约整批保存约 6 ms，整轮结果增量保存约 109 ms，读取探针接口约 50 ms，未变化轮询约 1.5 ms。这是合成存储负载，不能代表所有上游的网络性能。实际容量取决于令牌数、每个令牌模型数和响应耗时，不能只按渠道数量判断。
